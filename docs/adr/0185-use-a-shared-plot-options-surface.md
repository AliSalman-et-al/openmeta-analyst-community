# Use a Shared Plot Options Surface

Status: accepted - post-cutover Post-Port Refactor; supersedes the pre-run style limitation in ADR 0180.

The Method & Parameters dialog should expose a general **Plots** tab, and the result context menu should expose **Edit Plot**. The pre-run Plots tab and the per-plot editor should present the same Plot Options Surface for currently editable forest plots: Forest Plot Style, Universal Appearance Controls, column labels and visibility, Default Forest Style raw-count/header/annotation toggles, axis settings, summary-line visibility, and output path.

The two surfaces differ by scope, not capability. The pre-run Plots tab writes global `fp_*` defaults applied to every plot generated by the next Results output. The per-plot editor writes only the selected Plot Artifact's persisted render params and regenerates that artifact.

ADR 0180 deliberately made `fp_style` selectable only after rendering so first generated plots always used Default Forest Style. Issue #269 changes that product decision: users need to choose RevMan or BMJ style, accent color, point-size multiplier, and visibility toggles before running an analysis instead of restyling each plot afterward.

## Consequences

- Existing R render contracts stay stable: the shared surface still writes the same `fp_*` params consumed by the Forest Render Bundle and metafor Forest Renderer.
- The generic Plots/Edit Plot labels prepare the UI for Meta-Regression Bubble Plot editing without renaming domain artifacts such as Forest Plot or Meta-Regression Bubble Plot.
- No Analysis Behavior changes; these options affect Plot Artifact presentation only.
